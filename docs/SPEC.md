# お絵描きWebアプリDrawing App 仕様書

- バージョン: 1.0
- 最終更新: 2026-09-11
- ステータス: MVP 実装済み（未決事項はすべて決着。結論は §16）

---

## 1. 概要と目的

自分用のスケッチ・ラフ描きのための、ブラウザで完結するお絵描きWebアプリ。

- 1人で使う。ログイン不要、サーバー不要。
- 描画処理はすべてブラウザ内（HTML Canvas）で完結する。
- 完成した絵は **PNG（背景白）** としてローカルにダウンロードする。
- **完全無料で運用する。** ランタイムでネットワーク通信を行わず、サーバー機能・DB・課金APIを一切使わない。Vercel Hobby（無料・個人非商用）＋ GitHub 公開リポジトリのみ。

### 設計上の最優先事項

1. **運用コスト 0**。静的アセットの配信だけで動く。バックエンド・外部API・フォントCDN等の実行時依存を持たない。
2. **描き心地**。ポインタ操作に対して遅延なく線が出る。
3. **シンプルさ**。MVP スコープを厳守し、機能を増やさない。

## 2. スコープ

### MVPに含む

- プリセットから選ぶキャンバスサイズでの新規作成
- ブラシ（太さ・色・不透明度）と消しゴム
- 取り消し・やり直し（Undo / Redo、深さ制限あり）
- 図形（矩形・楕円）、直線、塗りつぶし（バケツ）、テキスト
  - 図形・直線・テキストは **確定前は調整可能** → 確定でキャンバスにラスタライズ
- PNG（背景白）としての書き出し
- キャンバス全体のクリア
- ライトテーマのUI
- PWA（Service Worker によるオフライン起動・インストール対応）
- PC（マウス / トラックパッド）での操作

### MVPに含まない（将来拡張の候補）

- レイヤー
- 作業内容の永続化・自動復元（ブラウザ内保存、クラウド保存）
- 複数人でのリアルタイム共同編集
- ペンタブ・スタイラスの筆圧、傾き
- スマホ・タブレットのタッチ最適化UI
- ダークテーマ / テーマ切替
- PNG以外の書き出し（JPEG / SVG / 透過PNG / クリップボードコピー）
- ベクター編集、オブジェクトの再選択・再編集（確定後）
- 画像の読み込み・貼り付け、トリミング、変形、フィルタ
- カスタムブラシ、ブラシテクスチャ、手ブレ補正の強度調整
- 取り消し履歴のブランチ管理
- アカウント、共有リンク、ギャラリー
- 多言語対応（UIは日本語のみ）
- アナリティクス、エラートラッキング（外部送信を伴うもの）

## 3. 用語

| 用語 | 意味 |
| --- | --- |
| ベースキャンバス | 確定済みの描画内容を保持するラスター（`<canvas>`）。書き出し対象 |
| プレビューキャンバス | 描画中のストローク／未確定の図形・テキストを表示する重ねレイヤー。書き出し対象外 |
| エンジン | DOM に依存しない描画コアロジック（塗りつぶし・色計算・図形幾何・スムージング・履歴）。単体テストの中心 |
| 確定 / コミット | 未確定の図形・テキストをベースキャンバスに描き込み、以後は Undo でのみ戻せる状態にする操作 |
| スナップショット | Undo/Redo のためにベースキャンバスの状態を丸ごと保存したもの |
| プリセット | キャンバスの初期サイズの定義（例: 1080×1080） |

## 4. 全体アーキテクチャ

```
[ブラウザ]
  Next.js (App Router) で配信される静的な単一ページアプリ
   └─ <PaintApp>  … クライアントコンポーネント
       ├─ Toolbar / ColorPicker / BrushSettings / NewDocumentDialog   （UI・React）
       ├─ CanvasStage                                                （2枚の <canvas> を重ねて配置）
       │    ├─ ベースキャンバス   … 確定済みの絵
       │    └─ プレビューキャンバス … 描画中／未確定のもの
       ├─ tools/*   … 各ツールの状態機械（pointer イベント → エンジン呼び出し）
       └─ engine/*  … DOM非依存のコア（fill / color / geometry / stroke / history / export）

[Service Worker]  … アプリシェルを precache ＋ ハッシュ付きアセットを cache-first。オフライン起動
```

- **サーバーコンポーネント／API ルート／サーバーアクションは使わない。** ページはビルド時に静的化される（SSG）。実行時のサーバー処理は0。
- Canvas 描画は素の **Canvas 2D API**。描画ライブラリは不使用。
- 状態はすべてメモリ上。リロード・タブを閉じると失われる（仕様。§9）。
- Google Fonts 等の CDN をランタイムで参照しない。フォントはシステムフォント、または自己ホスト（オフライン動作とコスト0のため）。

## 6. 機能要件

### 6.1 新規作成とキャンバス

- 初回アクセス時、または「新規作成」時に **プリセット選択ダイアログ** を表示する。
- プリセット（`src/config/presets.ts`、初期案・調整可）:

  | 名称 | サイズ (px) |
  | --- | --- |
  | 正方形（小） | 720 × 720 |
  | 正方形（大） | 1080 × 1080 |
  | 横（HD） | 1280 × 720 |
  | 縦（ソーシャル） | 1080 × 1350 |
  | 横（FHD） | 1920 × 1080 |

- 最大寸法の上限 `MAX_CANVAS_DIMENSION`（初期案 2048px）を超えるプリセットは置かない（メモリ・性能保護）。
- 新規作成時、ベースキャンバスを **不透明な白** で塗りつぶす。
- キャンバスは画面中央に表示。ウィンドウより大きい場合は縮小表示（表示倍率）。ズーム・パンは入れない。
- 「新規作成」「クリア」など現在の描画内容が失われる操作の前に、アプリ内の確認ダイアログを表示する（`beforeunload` によるブラウザ警告は出さない。§9）。

### 6.2 ツール

共通の描画設定: **色**（カラーピッカー）、**ブラシ太さ**（`BRUSH_MIN`〜`BRUSH_MAX`、既定 4px）、**不透明度**（0〜100%、既定 100%）。

| ツール | 挙動 |
| --- | --- |
| ブラシ | pointerdown〜up でフリーハンドの線。線はスムージングして描画（§7 性能）。色・太さ・不透明度を反映 |
| 消しゴム | ブラシと同じ操作で、**白**を描く（背景が白で透明・レイヤーが無いため。太さ設定を共有） |
| 直線 | pointerdown で始点、ドラッグで終点。離すと「未確定」状態（後述） |
| 矩形 | 対角の2点。塗りつぶし有無のトグル（塗り色は現在の色）。線幅はブラシ太さ |
| 楕円 | 矩形と同様、外接矩形で定義 |
| 塗りつぶし（バケツ） | クリック位置から連結領域を flood fill。許容差 `FILL_TOLERANCE`（既定 16 / 255）。不透明度は下地に合成した色に畳み込んでから塗る（キャンバスを半透明にしないため） |
| テキスト | クリックした位置にテキスト入力オーバーレイを表示。フォントサイズ・色を反映。日本語入力（IME）対応 |

### 6.3 未確定オブジェクトの調整（直線 / 矩形 / 楕円 / テキスト）

- 操作完了（pointerup、またはテキスト入力開始）後、対象は **プレビューキャンバス上の「未確定」状態** になる。
- 未確定状態でできること:
  - **移動**: 本体をドラッグ
  - **リサイズ**: バウンディングボックスのハンドル（四隅＋各辺）をドラッグ。判定半径は図形の短辺の 1/3 を上限とし、小さい図形でも中央を掴んで移動できるようにする。直線は端点をドラッグする。テキストはハンドルを持たず、フォントサイズを設定パネルから変える
  - **テキスト**: 内容の再編集、フォントサイズ変更
- **確定のトリガー**: Enter キー / 別ツールへの切替 / キャンバスの他の場所をクリック / 「確定」ボタン
- **キャンセルのトリガー**: Esc キー（未確定オブジェクトを破棄）
- 確定するとベースキャンバスに描き込まれ、履歴に1ステップとして積まれる。以後の修正は Undo のみ。
- 同時に未確定オブジェクトは1つだけ（新しい操作を始めると、既存の未確定オブジェクトは自動確定）。

### 6.4 取り消し・やり直し（Undo / Redo）

- スナップショット方式。1つの「ユーザー操作」= 1ステップ:
  - ブラシ／消しゴムの1ストローク（pointerdown〜up）
  - 図形・直線・テキストの確定
  - 塗りつぶし
  - クリア
- 履歴の深さは `HISTORY_DEPTH`（既定 20）。超過したら最古を破棄（それより前には戻れない）。
- 線形履歴。Undo 後に新しい操作を行うと、それ以降の Redo 分は破棄される。
- スナップショットは `PixelBuffer`（生ピクセル）で保持する。読み書きが同期で済み、取り消しの連打と確定処理の競合を構造的に避けられる。総メモリの上限（`HISTORY_MAX_BYTES`）を超えたら最古から破棄する。
- ショートカット: Undo = `Ctrl/Cmd + Z`、Redo = `Ctrl/Cmd + Shift + Z` および `Ctrl + Y`。

### 6.5 書き出し

- 「PNGで保存」操作で、ベースキャンバス（背景白・不透明）を `image/png` にエンコードしてダウンロード。
- 未確定オブジェクトがある場合は先に確定してから書き出す。
- ファイル名: `drawing-YYYYMMDD-HHmmss.png`（ローカル時刻。`src/engine/export.ts` で生成）。
- 書き出しはブラウザのダウンロード機能のみを使う（サーバー送信なし）。

### 6.6 クリア

- ベースキャンバスを白で塗り直す。確認ダイアログを経る。履歴に1ステップ積む（Undo で戻せる）。

## 7. 非機能要件

| 分類 | 要件 |
| --- | --- |
| コスト | 実行時の外部依存 0。静的配信のみ。§5「コスト0の根拠」 |
| 性能 | pointermove の描画は `requestAnimationFrame` でバッチ。1080×1080 程度で体感遅延なく線が追従すること。flood fill はメインスレッドで実行（大サイズで問題が出たら Web Worker 化を検討） |
| メモリ | 履歴スナップショットの枚数・総バイト数に上限。キャンバス寸法に上限 |
| オフライン | 一度読み込めば、以降はオフラインで起動・全機能利用可能（書き出し含む） |
| 対応ブラウザ | 最新2バージョンの Chrome / Edge / Firefox / Safari（デスクトップ）。Pointer Events API・`canvas.toBlob` 前提 |
| アクセシビリティ | ツールはネイティブ `<button>` ＋ `aria-label`／`aria-pressed`。キーボードショートカット（§8）。フォーカス可視。コントラスト比 AA。キャンバス自体は代替不可のため、操作系に説明を付す |
| プライバシー | データ収集なし。Cookie なし。ネットワーク送信なし。プライバシーポリシーは「何も収集しない」旨の短い記載で足りる |
| セキュリティ | ユーザー入力はテキストのみ。DOM への挿入時は React の標準エスケープに委ね、`dangerouslySetInnerHTML` を使わない。外部スクリプトを読み込まない。CSP とセキュリティヘッダは `vercel.json` で配信時に付与する |
| ライセンス | リポジトリは公開。MIT（`LICENSE`） |
| 国際化 | UI 文言は日本語。将来の多言語化に備え文言は1ファイルに集約 |

## 9. 永続化について

- **永続化しない。** 作業内容はメモリ上のみ。リロード・タブクローズで消える。
- `beforeunload` による離脱警告は **出さない**（ユーザー選択による）。
- 唯一残せる成果物は、ユーザーが明示的に書き出した PNG ファイル。
- 破壊的なアプリ内操作（新規作成 / クリア）だけは、直前にアプリ内確認ダイアログを挟む。

## 11. 主要モジュール（DOM非依存エンジン）

`src/engine/` — Canvas / DOM に触れず、プレーンなデータ（`Uint8ClampedArray` / `{r,g,b,a}` / 座標）だけを扱う。テストの中心。

| モジュール | 責務 |
| --- | --- |
| `color.ts` | HEX ⇔ RGBA 変換、不透明度を考慮したピクセル合成（source-over） |
| `geometry.ts` | 2点から矩形・楕円・直線を正規化（負の幅/高さの吸収、正方形/45度スナップ等の将来余地） |
| `stroke.ts` | ポインタ座標列 → スムージングされた描画パス（例: Catmull-Rom / 二次ベジェ）。太さ・不透明度は描画側で適用 |
| `fill.ts` | flood fill。入力: ピクセル配列・幅・高さ・開始点・塗り色・許容差。出力: 変更後の配列（または変更マスク） |
| `history.ts` | Undo/Redo スタック。push / undo / redo / canUndo / canRedo、深さ・総バイト上限、Undo 後 push での Redo 破棄 |
| `export.ts` | 書き出しファイル名生成、白背景合成の仕様（背景がすでに白なら透過ピクセルを白に） |
| `types.ts` | 共通型（`Rgba`, `Point`, `Rect`, `ToolId`, `Preset` など） |

`src/canvas/` と `src/tools/` は、上記エンジンと Canvas 2D API を結ぶ薄いアダプタ層に留める。

## 13. テスト方針（Vitest）

グローバル指針（`~/.claude/CLAUDE.md`）を厳守する。実機能を検証し、無意味なアサーションやテスト用ハードコードを書かない。境界値・異常値を必ず含める。

### 単体テスト（エンジン中心 = 必須）

DOM 非依存モジュールを、実データに対する実アルゴリズムで検証する。

- **`color.ts`**
  - `#RRGGBB` / `#RGB` のパース、無効入力（`#12`, `xyz`, 空文字）でエラー or 既定
  - 不透明度 50% の赤を白の上に合成 → 期待 RGBA を数値で検証
  - 不透明度 0% / 100% の境界
- **`geometry.ts`**
  - 始点が終点より右下・左上・同一の各ケースで、正規化された `Rect` の x/y/w/h
  - 幅0・高さ0（クリックのみ）の扱い
  - 楕円の外接矩形、直線の端点保持
- **`stroke.ts`**
  - 2点 → 直線的なパス
  - 3点以上 → 制御点が入り、始点・終点は入力を保持
  - 重複点・1点のみの入力で例外を出さない
- **`fill.ts`**
  - 小さな合成ピクセル配列（例 5×5）で、単色領域をクリック → その領域だけが塗られる
  - 対角接続は塗らない（4連結）
  - 許容差: 近い色は塗る / 離れた色は塗らない の境界
  - 開始点が既に塗り色 → 変化なし（無限ループしない）
  - キャンバス端の領域が正しく塗られる
- **`history.ts`**
  - push → undo → redo で状態が一致
  - 深さ `HISTORY_DEPTH + 1` 回 push 後、最古が失われ、最新から `HISTORY_DEPTH` 回 undo できる
  - undo 途中で push → redo 不可になる（redo スタックが空）
  - 空状態で undo/redo しても壊れない（`canUndo`/`canRedo` が false）
- **`export.ts`**
  - 既知の時刻を注入 → ファイル名が `drawing-YYYYMMDD-HHmmss.png`
  - 透過ピクセルを含む配列 → 白背景合成後に不透明の白になる

### コンポーネント／統合テスト

- Canvas を伴う結合は、可能な範囲で **Vitest browser mode（`@vitest/browser` + Playwright プロバイダ）** で実施（`pnpm test` の範囲内・Vitest ランナー）。困難なものは §14 の手動QAで担保する。
  - ツール切替で未確定オブジェクトが自動確定される
  - `Ctrl+Z` / `Ctrl+Shift+Z` が Undo/Redo を呼ぶ
  - 「PNGで保存」で `toBlob` → ダウンロードが1回起きる（ダウンロード契機のみ検証）
  - 「クリア」→ 確認 → キャンバスが白 1色になる（数ピクセルサンプルで検証）
- モックは「システムクロック」「ブラウザのダウンロード契機」に限定。描画ロジックはモックしない。

### やらないこと

- E2E（Playwright 単体スイート）は当面作らない（ユーザー選択）。将来必要になれば追加。

### 実装時に判明し、仕様に反映した事項

- **ハンドルの判定半径は図形の短辺の 1/3 を上限にする。** 固定 10px のままだと小さい図形で判定範囲が図形全体を覆い、本体をドラッグして移動できなくなる。幅・高さ 0 の図形は移動のみになるため、Esc で破棄して描き直す。
- **塗りつぶしは下地に合成した色で塗る。** 設定色をそのまま書き込むと、不透明度が 1 未満のときにキャンバス自体が半透明になる。
- **テキストの四隅ハンドルによるリサイズは実装しない。** フォントサイズは設定パネルから変更する（§6.3 の「フォントサイズ変更」は満たす）。
- **PWA は Serwist ではなく自前のサービスワーカー。** 依存を増やさず、`output: "export"` との相性を気にせずに済み、キャッシュ戦略を純粋関数としてテストできる。
- **履歴の「深さ 20」は Undo できる回数が 20。** 保持するスナップショットは「現在の状態 + 20 件」= 21 件。
