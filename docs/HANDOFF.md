## 3. このプロジェクトで絶対に外さない制約

`CLAUDE.md` に詳しく書いてあるが、**最重要なので再掲する**。ここを壊す提案をしてはいけない。

1. **運用コスト 0 を維持する。** これはユーザーが最初に出した要件で、技術選定のすべてがここから来ている。
2. **実行時に外部通信をしない。** 外部 API・CDN・Google Fonts・アナリティクスを入れない。
   フォントはシステムフォントのみ（だから PWA のキャッシュ対象にフォントが無い）。
3. **サーバー処理を作らない。** API ルート / Route Handler / Server Actions / DB / 認証を追加しない。
   これを入れた瞬間に Vercel の Function 課金の対象になる。
4. **CI が上記を機械的に検査している。** `scripts/check-no-external-refs.mjs` が `out/` を走査し、
   外部オリジンへの参照が 1 つでもあればビルドを失敗させる。約束を人の注意力に頼らせていない。
5. **描画ロジックをモックしない。** テストは `@napi-rs/canvas` の実 2D コンテキストに描いて
   `getImageData` で実ピクセルを検証する。モックしてよいのは「システムクロック」と
   「ブラウザのダウンロード契機」だけ。
6. **テストを通すためのハードコードを本番コードに入れない。** `if (testMode)` 分岐や
   テスト専用のマジックナンバーは禁止。設定値は `src/config/constants.ts` に集約する。

## 4. アーキテクチャの一行まとめ

```
React UI  →  PaintSession  →  tools（純粋な状態機械）  →  engine（DOM非依存）
                  ↓
        canvas アダプタ → <canvas> 2枚（ベース＝確定した絵 / プレビュー＝描画中）
```

- **依存の向きは一方通行。** `src/engine/` は DOM にも Canvas にも触れない。プレーンなデータだけを扱う。
  だからこそ Node 上で実ピクセル検証ができ、テストの中心になっている。
- `PaintSession` は React から独立したアプリ状態クラス。UI レベルの挙動をヘッドレスで検証できる。
- 新しいロジックを足すときは **まず `src/engine/` に DOM 非依存で書き、テストしてから UI に繋ぐ**。

全体像を 1 枚にした図がある（ローカル → GitHub → Vercel → ブラウザ）:

## 5. ユーザーとの進め方（これが一番引き継ぎにくい部分）

- **日本語でやり取りする。**
- **git はユーザー自身が打つ。** 「git の練習をしたい」という意向があるため、こちらが代行しない。
  ユーザーがコマンドを打ち、**おかしなことをしていたら指摘する**のがこちらの役割。
  実際にこれまで、`git add .` の危険性、コミットメッセージと中身の食い違い（`--amend` で修正）、
  `git branch -m` による `main` の誤改名（ローカルのみなので復旧）などを指摘して直してきた。
  指摘するときは「何が起きたか」「なぜ安全／危険か」「どう直すか」を添える。
- **GitHub の練習もしたい。** ブランチ → PR → CI → マージ → ブランチ削除、の一周を実際にやりたがっている。
  ただし **不要なブランチを勧めない**。以前「コードの書き換えがいらないなら新しいブランチいらないじゃん」
  と正しく指摘されている。理由がないならないと言う。
- **タスクが終わったら `docs/TODO.md` のチェックボックスにチェックを入れる。** 毎回頼まれる。
  ただし**実際に検証していない項目にチェックを入れてはいけない**。未検証なら理由を添えて残す。
- **ライブラリの調査には context7 を使う**ようたびたび指示される。
- **推測で実装しない。** 仕様が曖昧なら確認する。これは `CLAUDE.md` にも明記されている。
- ユーザーは鋭い。事実と違うことを言うとすぐ気づかれるし、実際に何度も正しく指摘されている。
  **できていないことを「できた」と言わない。** 検証の範囲を正確に述べる。

## 6. 環境の注意点

- **`sudo` が使えない**（TTY なし）。root 権限が要る手順は通らない。
  ブラウザ検証は `apt-get download` + `dpkg -x` + `LD_LIBRARY_PATH` で共有ライブラリ
  （`libnspr4` / `libnss3` / `libasound2t64`）を作業ディレクトリに展開して解決した。システムには触っていない。
- **pnpm 12 を使っている。** ビルドスクリプトの許可は `package.json` の `onlyBuiltDependencies` ではなく
  `pnpm-workspace.yaml` の `allowBuilds:` で指定する（前者は無視される）。
- Serwist は**使っていない**。pnpm 12 でシンボリックリンクが壊れる問題に当たり、
  サービスワーカーを自前で書くことにした。結果として依存が 17 個減り、戦略を純粋関数として
  テストできるようになった。経緯は `docs/TODO.md` の P13。
